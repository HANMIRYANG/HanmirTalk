# 05. 메신저 명세

## 메시지 타입

- text
- image
- file
- notice
- system
- task_reference
- decision_reference

## 채팅방 타입

- direct: 1:1 채팅
- group: 일반 단체방
- department: 부서방
- announcement: 공지방
- project: 프로젝트방

## 메시지 기능

- 전송
- 조회
- 검색
- 수정 (작성자 본인)
- 삭제 처리 soft delete
- 파일 첨부
- 이미지 첨부
- 읽음 처리 (방 단위 `lastMessageId` 마킹)
- 상단 고정 (방당 1개)
- 스레드 답글 (깊이 1, 부모 메시지에 답글 수/최근 답글 요약 표시)
- 이모지 반응 (화이트리스트 6종: 👍 ✅ 🙏 🎉 👀 📌, 추가/제거 idempotent)
- 예약 전송 (예약 생성/목록/취소, 도래 시 서버 poller가 전송)
- 메시지에서 업무 만들기
- 메시지에서 결정사항 만들기

## 읽음 표시

- 방 단위 `lastMessageId` 마킹 방식 — 클라이언트가 `POST /rooms/:roomId/read`로
  마지막으로 본 메시지 id를 보내면 그 시점까지 읽음 처리 (메시지 개별 읽음 아님)
- 공지: 확인자/미확인자 명단 (공지 확인 버튼 기준, 별도 집계)

## 알림

- 새 메시지
- 나에게 배정된 업무
- 업무 마감 임박
- 공지 등록
- 프로젝트 상태 변경
- 내가 언급된 메시지

## 채팅 입력창 명령어

채팅 입력창에서 빠른 업무 호출을 지원한다. 기존 채팅 UI 디자인은 유지하고, 입력 보조 레이어(팝오버)로만 동작해야 하며 일반 메시지 작성 흐름을 방해해서는 안 된다.

### `@` 멘션 / 태그

#### 지원 범위

- `@사용자명`: 특정 사용자 멘션
- `@부서명`: 부서 멘션
- `@프로젝트코드` 또는 `@프로젝트명`: 프로젝트 참조
- `@업무코드`: 업무 참조 (예: `@T-1024`)
- `@파일명`: 파일 참조

#### 동작

- 입력창에서 `@` 입력 시 검색 팝오버 표시
- `@` 뒤에 입력한 텍스트로 사용자/부서/프로젝트/업무/파일 후보를 통합 검색
- 후보 항목은 타입 아이콘과 라벨로 구분 (예: `[👤 사용자] 김민준 책임 · 생산기술팀`)
- 선택 시 메시지 본문에 structured mention 토큰 삽입
- 전송 시 message payload에 `entities` 또는 `mentions` 필드를 포함하여 백엔드로 전송
- 백엔드는 멘션 대상에게 알림을 생성할 수 있어야 함 (사용자/부서 멘션 → 새 알림 타입 발급)

#### 권한/보안

- 사용자가 접근 가능한 사용자/부서/채팅방/프로젝트/파일 범위 안에서만 후보를 노출
- 권한 없는 리소스가 검색 결과에 포함되지 않도록 백엔드 `GET /mentions/search`에서 필터링
- 멘션 토큰이 본문에 포함되더라도, 수신자 권한 검사는 알림 발급/링크 클릭 시점에 한 번 더 수행

### `/` AI 명령어

#### 지원 명령 (구현된 5종)

- `/요약`: 현재 채팅방 최근 메시지 요약
- `/업무추출`: 대화에서 업무 후보 추출
- `/결정사항`: 최근 대화에서 결정사항 후보 추출
- `/공지초안`: 대화 내용을 기반으로 공지 초안 작성
- `/회의록`: 최근 대화를 회의록 형식으로 변환

#### 동작

- 입력창 첫 글자 또는 공백 뒤 `/` 입력 시 명령어 팝오버 표시
- 명령어 선택 후 범위(scope) 선택 단계 노출
  - 최근 20개 메시지
  - 오늘 대화
  - 선택한 메시지
  - 특정 스레드
- 명령 실행 결과는 **자동 전송 금지**. 입력창 위쪽에 AI 초안 미리보기 패널로 표시
- 사용자가 "삽입" 또는 "전송"을 선택해야 실제 메시지로 반영
- 결과 메시지는 `system` 또는 `ai_draft` 성격으로 구분 (메시지 타입 또는 `ai_generated` 플래그)
- AI 결과에는 "AI 생성 초안" 뱃지 표시 의무

#### 권한/보안 원칙

- AI 명령은 **현재 사용자가 볼 수 있는 메시지/파일/프로젝트만** context로 사용 (백엔드에서 권한 필터 후 모델 호출)
- 파일 원문 요약 (`/요약`이 첨부 파일 포함 시)은 파일 접근 권한을 확인한 뒤에만 허용
- 민감 정보가 포함될 수 있으므로 자동 전송 금지 — 반드시 사용자 확정 단계 필요
- AI 생성 업무/결정사항 후보는 자동으로 `tasks` / `decisions` 테이블에 insert하지 않고, 사용자가 명시적으로 확정한 시점에 생성

### 데이터 모델 영향 (messages)

`messages` 테이블에 다음 필드를 단계적으로 도입한다.

- `entities` JSONB: 본문에 포함된 멘션/참조 목록 — `[{ type: "user"|"department"|"project"|"task"|"file", id, label }]`
- `ai_generated` BOOLEAN DEFAULT false
- `ai_command` VARCHAR(50): 사용된 AI 명령어 (`summary`, `extract_tasks` 등)
- `source_message_ids` UUID[]: AI 요약/정리에 사용된 원본 메시지 ID 목록

### MVP 포함 여부

- `@` 사용자 멘션: **MVP 포함 가능** (우선순위 1)
- `@` 부서/프로젝트/업무/파일 참조: MVP 후반 또는 MVP+
- `/` AI 명령어 전체: **MVP+ 권장**
- 단, 데모 가치가 중요하면 `/요약`만 제한적으로 MVP에 포함 가능

### 구현 우선순위

1. `@` 사용자 멘션
2. `@` 프로젝트/업무/파일 참조
3. `/요약` 최근 메시지 요약 초안
4. `/업무추출`, `/결정사항` 초안
5. AI 초안 확정 → `tasks` / `decisions` / `notices` 생성 연동
6. 파일 내용 기반 AI 요약
